# Finance V1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 用户未要求提交或推送，不执行 Git 发布操作。

**Goal:** 将已存在的个人财务 Skill 改为重复使用结果稳定、可修正、可撤销、能保护用户笔记的 V1.1。

**Architecture:** 保留 `scripts/finance.py` 作为兼容 CLI 和公共函数入口。按测试驱动增量抽出存储安全、匹配规则与报告生成模块；先保证现有测试兼容，再新增用户可观察行为。SQLite 为事实来源，Markdown/分析 JSON/Bases 为派生产物。

**Tech Stack:** Python 3.9+ 标准库、SQLite、unittest、Markdown、可选 Obsidian Bases。

**Spec:** [已确认规格](../specs/2026-10-22-finance-v1.1.md)

## Global Constraints

- 执行规格中的全部约束；Python 3.9+，仅标准库，默认 CNY，原始记录保留。
- 不联网处理账单，不使用真实数据，不修改全局配置，不提交或推送。
- 任何生产代码修改前先运行相应失败测试；每个任务完成时运行完整测试集。
- 现有公共 CLI 命令和测试调用继续可用；新增字段对旧 CSV 有明确兼容默认值。
- 用户确认的是功能方向；本计划尚待执行方式确认。

## Review Focus

1. 不同文件、不同顺序导入同一交易；含无 ID 的真实同金额多次购买 → Task 1/2。
2. 已人工关联、部分退款、多次退款、后到候选或先到退款 → Task 2。
3. 撤销批次时，另一个批次仍然支持同一规范交易 → Task 3。
4. 旧库、旧月报、手写备注、报告写入失败及配置无效 → Task 1/4。
5. 空账本、只有负债、截图覆盖不完整、未确认现金到账 → Task 2/5。

## 文件分工

- `scripts/finance.py`：CLI、兼容入口与工作流编排。
- `scripts/finance_storage.py`：版本迁移、备份、原子文件写入和导入批次。
- `scripts/finance_matching.py`：账户隔离、重复候选、退款分配与人工决定。
- `scripts/finance_reports.py`：月度指标、分析指纹、受保护 Markdown 与面板。
- `tests/test_finance_v11.py`：连续使用回归；`tests/test_finance_storage.py`：旧库和失败恢复测试。
- `SKILL.md`、`references/*.md`、`README.md`：意图路由、操作契约和安装体验。
- `assets/demo-transactions.csv`、`assets/Finance.base`：演示输入与可选索引。

## Task 1 — 导入身份、溯源和安全存储

**Files:** 修改 `scripts/finance.py`；新建 `scripts/finance_storage.py`、`tests/test_finance_v11.py`、`tests/test_finance_storage.py`；更新统一 CSV 字段说明与模板。

**Interfaces:**
- 保留 `init_vault(vault: Path) -> None`、`import_file(vault: Path, source_file: Path) -> int`。
- 新增 `import_with_receipt(vault: Path, source_file: Path, *, coverage: str = "unknown", source_reference: str = "") -> dict`；回执含 `batch_id`、`inserted_count`、`duplicate_count`、`affected_months`。
- 存储模块提供 `migrate_database(connection, backup_dir: Path) -> None` 和 `atomic_write_text(path: Path, text: str) -> None`。
- 新字段包括来源定位、币种、覆盖状态和批次归属；旧 CSV 缺少币种默认 CNY，覆盖不默认完整。

- [ ] 写失败测试：周账单 100 元、月账单重复 100 元加 50 元，净消费必须为 `150.00`，原始行仍有 3 条；重复同文件新增为 0；两个不同账户同号不合并；无 ID 同商户同金额两笔保留。
- [ ] 写失败测试：非 CNY/无效日期/负数或非有限金额拒绝且无部分交易写入；来源原始额外列保留；旧库迁移保留数量及人工记录；注入文件替换失败后旧文件完整。
- [ ] 运行 `python3 -B -m unittest discover -s tests -p 'test_finance_v11.py' -v` 和存储测试，记录预期失败。
- [ ] 实现来源观测与规范交易的区分；按账户+平台+可信 ID 去重。无 ID 仅生成疑似重复，不自动抵消。迁移使用版本标识和 SQLite 备份，归档不覆盖。
- [ ] 运行 `python3 -B -m unittest discover -s tests -v`，全部通过后继续。

## Task 2 — 稳定退款、状态分类与待确认

**Files:** `scripts/finance.py`、新建 `scripts/finance_matching.py`、`tests/test_finance_v11.py`、`references/accounting-rules.md`。

**Interfaces:** 保留 `match_refunds(connection)`、`match_duplicates(connection)`、`link_refund_manually(vault, refund_id, purchase_id)` 兼容入口。新增 `list_reviews(vault: Path) -> list` 和 `unlink_refund(vault: Path, refund_id: str) -> None`；复核项含稳定 ID、类型、金额、来源、候选及说明，展示序号只是当前视图标签。

- [ ] 写失败测试：重复运行不新增虚假待确认；人工 A 关联在导入 B 后仍是 A；不同账户退款不相连；无唯一候选不自动匹配。
- [ ] 写失败测试：100 元购买先后退 30/70 元，净消费为 0；任意导入顺序一致；同号冲突不取 SQL 第一行；超额退款待确认；撤销人工关联后不得立刻自动恢复同一配对。
- [ ] 写失败测试：交易关闭不计消费；退款状态不等于单独退款事件；未知交易进入复核；未经确认的个人转账不直接视为内部转账；花呗退款仅冲减债务时现金到账为 0，结算未知时明确未知。
- [ ] 运行新增测试观察失败，再实现稳定分配、人工覆盖优先、拒绝/解除记录、类型与结算验证。
- [ ] 运行完整测试集，并验证跨平台去重后的退款作用于规范消费而不是被排除的来源副本。

## Task 3 — 分类修正、操作回执与撤销导入

**Files:** `scripts/finance.py`、`scripts/finance_storage.py`、`scripts/finance_matching.py`、`tests/test_finance_v11.py`。

**Interfaces:**
- `set_category(vault: Path, transaction_id: str, category: str, scope: str = "transaction") -> dict`，scope 为 `transaction`、`merchant-future` 或 `merchant-all`。
- `reclassify(vault: Path) -> dict` 重算未被人工单笔覆盖的历史分类。
- `undo_import(vault: Path, batch_id: str) -> dict` 撤回批次影响，保留原始行和历史操作。
- CLI 增加 `review`、`categorize`、`reclassify`、`undo-import`、`unlink-refund`，支持 JSON 回执供 Agent 使用。

- [ ] 写失败测试：三种分类范围互不混淆；单笔人工分类在重建和规则修改后不变；显式重分类将历史“购物”改为“学习”。
- [ ] 写失败测试：撤销一个重叠批次不会删除另一批次的有效消费；重复撤销不产生变化；退款批次撤销恢复购买净额；原始文件/行与操作记录保持。
- [ ] 写失败测试：回执只统计本次变化，列出受影响原购买月及前后差额；失败导入不能显示成功回执。
- [ ] 运行上述测试观察失败，再实现人工覆盖、批次状态和可追溯回执；回执文件使用原子写入。
- [ ] 运行完整测试集。

## Task 4 — 保护月报与使旧分析失效

**Files:** `scripts/finance.py`、新建 `scripts/finance_reports.py`、`tests/test_finance_v11.py`、`references/analysis-rules.md`。

**Interfaces:** 保留 `build_month(vault, month) -> Path` 和 `build_all_months(vault) -> list`；新增 `write_analysis(vault: Path, month: str, input_fingerprint: str, findings: str, suggestions: str) -> None`。分析输入使用规范 JSON 指纹，拒绝基于过期指纹写入。

- [ ] 写失败测试：手写备注在重建后逐字保留；输入未变时旧分析保留；跨月退款将原月消费归零后旧分析不再作为当前分析显示。
- [ ] 写失败测试：旧版无生成区标记的月报先备份并保留所有用户文字；标记损坏时不覆盖；过期分析写入明确失败。
- [ ] 运行新增测试，确认失败原因是现有整页覆盖/无失效机制。
- [ ] 实现受管理内容区、独立用户区、旧页保护迁移与输入指纹；只更新受影响月份，或保证全量重建不会改变不相关用户内容。
- [ ] 运行完整测试集，包括原有“重建保留分析”场景。

## Task 5 — 可信 Dashboard、覆盖信息与可选 Bases

**Files:** `scripts/finance_reports.py`、`scripts/finance.py`、`tests/test_finance_v11.py`、新建 `assets/Finance.base`。

**Interfaces:** 月报分析上下文新增 `coverage`、`review_amount`、`analysis_status`、`input_fingerprint` 和来源信息；`build_all_months` 无交易时仍生成首页、复核和质量页。负债缺失值用 null，生成页面显示未知。

- [ ] 写失败测试：空 Vault/只有负债快照均产生首页；缺失负债不显示已知零负债；最新账单 7 月不会标成当前 10 月；部分覆盖贯穿月报、JSON 和首页。
- [ ] 写失败测试：未知交易复核数量/金额非零；月度分类汇总等于净消费；全额退款不出现在习惯分析输入；退款核对页能回到来源。
- [ ] 写失败测试：覆盖不可比时不给环比结论；历史快照明确截止日期；手写首页备注重建不丢失。
- [ ] 运行失败测试后实现数据状态、分类/趋势表、待办入口、月报导航和退款核对页。
- [ ] 添加可选 Bases 月报索引，仅依赖扁平 Properties；不把 Bases 当作核心写入条件。

## 执行方式建议

推荐 **Native：在当前会话直接实现，最后独立审查**。退款、去重、批次撤销和报告之间共享状态较多，由同一实现者串行完成能减少接口反复；只将 Skill 行为测试和最终独立审查交给子代理。另一选项是 **Subagent-driven：逐任务独立实现和评审**，需要更多独立上下文。
