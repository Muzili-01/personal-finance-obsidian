# Personal Finance Obsidian V1.1 — 可放心日常使用

## 已确认的方向

本规格整理自 2026-10-22 的项目审查及用户“确认修改”。保留 Agent Skill + Python 确定性处理 + SQLite 总账 + Obsidian 展示架构，先修可信性，再改善自然语言操作和面板。不是独立 App，不引入银行登录、云端账单服务或自动投资建议。

## 必须保持的约束

- Skill 内容继续位于仓库根目录，兼容 Codex 与 Claude Code。
- Python 3.9+，运行时只使用标准库；金额使用整数分或 Decimal。
- 原始文件和原始行不删除、不改写；展示可以重新生成。
- 全额退款的购买与退款不进入消费明细或习惯分析，部分退款展示净消费；跨月退款修正购买月。
- 消费、资金实际流动、负债变化分开；没有到账证据不能推断现金到账。
- 自动决定必须可解释；人工决定优先且可撤销；多个候选不猜测。
- 默认只处理 CNY。其他币种明确拒绝，不无声按人民币汇总。
- 不覆盖用户的配置或笔记；所有验证使用合成数据和临时 Vault。
- 不主动联网或上传账单；保留云端 Agent、未加密存储和同步复制的隐私说明。
- 本次不提交、不推送、不安装到用户其他目录，不触碰真实财务数据库。

## 交付范围及验收

### A. 可靠导入与退款

1. 同一文件重复导入，以及不同导出文件含有同一平台交易号，都不重复计费；原始来源仍保留。无交易号的相似交易仅形成候选，不把真实重复购买误合并。
2. 匹配按账户与平台隔离。账户身份不明确时报告限制；无 ID 的退款证据不足则待确认。
3. 重复运行不能重新分配已确认退款；新增候选应暴露冲突，不悄悄改变用户决定。
4. 覆盖全额、部分、多笔退款、跨月、退款先导入、重复订单号及信用卡/支付平台双来源。
5. 验证日期、金额、类型、方向、币种和交易状态。失败交易不计消费；未知类型、账户不明的转账和退款状态歧义进入复核。
6. 归档保留来源原始列。截图标准化数据可关联归档文件及页/行/位置；可见范围不等于完整账期。

### B. 修正、撤销与安全存储

1. 单笔分类覆盖、商户未来规则、重分类历史数据为三个明确范围；单笔人工覆盖优先。
2. 导入按批次记录并生成回执：新增、重复、退款、待确认、影响月份、消费变化和产物路径。
3. 撤销指定导入批次只撤回其统计影响，保留原始数据、审计记录及其他批次提供的同一交易依据；再次撤销是幂等操作。
4. 引入数据库版本迁移及迁移前备份。生成文件原子替换，发生失败不能留下半个 JSON/Markdown。

### C. 月报与 Dashboard

1. 自动生成区与用户区分开。旧版月报迁移前备份；不能安全识别时保留旧页，不猜测覆盖范围。
2. 以分析输入指纹判断旧分析是否失效。输入未变保留；输入改变则标记待更新，不把旧分析当作当前结论；旧文可留在历史备份。
3. 每月输出覆盖范围、来源、待确认数量与金额、分类缺失、更新时间及分析状态。只有截图不得显示“已对平”。
4. 没有账单或负债快照显示未知，不使用 0 代替；只有负债快照或空 Vault 也能生成可用首页。
5. 首页展示最新数据月份、数据状态、消费分类、需要处理的事项、月报入口；退款核对页与消费分析分开。
6. 提供月度趋势表，仅在覆盖可比时生成比较结论。Bases 为可选月报索引，不依赖社区插件。

### D. Skill 与上手流程

1. 路由到首次设置、导入账单、处理待确认、修改分类、查看报告、撤销导入，不让每次请求走全流程。
2. 首次设置检查 Vault、Python 和写权限；已有配置不反复询问。路径只保存在用户授权的目标 Vault/工作区，不扫描或修改全局配置。
3. 提供无真实信息的演示账单。读取已有月报无需重新导入或写数据。
4. 用户用自然语言选择复核候选；系统内部处理 ID 和 CLI。普通流程必须由 Agent 调用确定性处理器，只有“用户手动调用 CLI”属于高级用法。
5. README 分别提供 Codex `$personal-finance-obsidian` 与 Claude Code `/personal-finance-obsidian` 示例，明确 Skill 仓库不是默认 Vault。
6. 建议只基于可验证数据，不推断购买动机、必要性或财务困境；不完整数据标记暂定。

## 不在本次实现

- 银行 API、自动登录、邮件抓取及无人值守同步。
- 多币种换算、投资或税务分析。
- OCR 服务、所有金融机构专用解析器；暂不支持的格式继续由 Agent 提取并复核。
- 独立 Web/App、交互式交易数据库插件或大型前端图表系统。
